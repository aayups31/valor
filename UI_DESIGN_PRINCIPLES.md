# VALOR interface direction

Recorded October 3, 2026 from the user's explicit preferences. Apply these principles to future demo and product work unless the user changes them.

- Aim for the restraint, clarity and craftsmanship of a premium consumer product: generous space, strong typography, subtle depth, calm motion and precise alignment.
- No boxy dashboard. Do not build a grid of bordered cards, square controls, nested panels or dense technical tables as the main experience. Use open compositions, flowing surfaces, rounded controls and deliberate separators.
- A person with no technical knowledge must be able to open the demo, start a mission and understand what is happening and why. Give the first screen one obvious starting action.
- Lead with the mission and real outcomes. Explain unfamiliar ideas in context with short, plain sentences. Reveal advanced controls and detailed records progressively.
- Make guidance feel integrated and minimal: a concise introduction, live narration, accessible help and an optional walkthrough. Avoid walls of instructions and compulsory onboarding.
- Show factual evidence from the engine. Distinguish attempted action, applied action, prediction and observed result. Label untested choices and finite forecasts honestly. Never invent an internal monologue or imply that all possible futures were evaluated.
- Use text and shape alongside color. Maintain keyboard navigation, visible focus, legible contrast, reduced-motion support and layouts that work on narrow screens.
- Keep the app local, lightweight and free of external font, asset, model or API dependencies. Do not add paid services for visual polish.

Review each future UI change against this document. A beautiful screen that obscures a failure or confuses a first-time user does not meet the brief.
