## What changed

The previous dark, bordered dashboard has been replaced with a warm, light composition: spacious typography, open sections, subtle depth, rounded controls and softly shaded maps. The main screen presents the mission and one starting action. Technical tables and raw JSON no longer dominate the experience. The page uses local system fonts, SVG and canvas; no external asset or API service was added.

The user journey is now:

1. Double-click **Start VALOR.cmd**, then press **Start the demo**.
2. Watch the direct-rule rover and comparison rover attempt the same mission.
3. Read their current situation and remaining battery, movement capacity and time.
4. Pause or advance **One decision** to read what was chosen, why, and the observed result.
5. Open **Explore the other options** to inspect selected, rejected and untested candidates.
6. Use the optional walkthrough/help, try another mission, change advanced settings or download both full records.
7. Double-click **Stop VALOR.cmd** to close the engine started by the launcher.

The interface explains damage, inability to move, depleted energy, missed deadlines, inspection and successful return in plain language. Descriptions use actual decision records and deterministic templates. They handle external braking and invalid-command overrides, and do not invent an internal monologue or claim exhaustive evaluation. Sample counts, forecast horizon, raw scores, sampling intervals and applied actions remain available in the detailed record.

Interaction improvements include stable candidate buttons during polling, keyboard focus, accessible disclosures/dialogs, reduced-motion support, responsive layouts, high-density canvas drawing, bounded request timeouts, stale-response protection and download feedback. Layout and interaction behavior are implemented but have not been verified in a rendered browser.

## Running without terminal commands

The Windows launcher starts the engine as a hidden background process and reuses an existing compatible VALOR server. A named mutex serializes startup/shutdown. Shutdown verifies the recorded process command and creation time before stopping its tree. Other services occupying the port are not replaced.

On this laptop, the installed project environment is reused. For another Windows machine, the launcher includes a setup path for the small simulator/demo dependencies when Python 3.11+ is present. That fresh-machine setup needs internet and has not been tested from an empty environment. The launcher does not install the optional PyTorch/SAC learning stack.

Closing a browser tab does not stop the engine; use Stop VALOR when finished. The launcher opens the default browser in normal use. During this work all launcher executions used `-NoBrowser`, respecting the declined browser-access request.
