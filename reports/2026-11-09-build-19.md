# Build report 19 — controlled supervision and live local pilot

**November 9, 2026.** Checkpoint 13 is closed for the disposable SQLite workflow. Checkpoint 14 passed its frozen gate for live tool execution by a local Llama 3.2 worker on synthetic data.

## Checkpoint 13

VALOR holds a proposal when its forecast shows that protected records would change. The local operator can explicitly approve or deny the exact held proposal using its receipt. Approval expires if another audit event intervenes or the rows change. Safe actions apply immediately. Receipts include the proposed changes and the pending-only alternative.

The write and its audit receipt commit in the same transaction. Retrying the same request returns its original receipt. Recovery restores the exact prior archive flags of the latest applied event, with a separate audit receipt, and refuses to overwrite newer work. Tests covered concurrent retries, denial, stale approval and recovery, audit failure, an unexpected trigger and abrupt process exit before commit. Separate CLI processes verified approval, denial and recovery on a fresh disposable fixture.

To try it in the project environment, choose a new path and run:

```powershell
.\.venv\Scripts\python.exe -m aace.supervision artifacts/operator-demo.sqlite3 init
.\.venv\Scripts\python.exe -m aace.supervision artifacts/operator-demo.sqlite3 propose trial archive_all
```

Use `approve trial RECEIPT_SHA256` or `deny trial RECEIPT_SHA256` in place of the proposal arguments. To restore an approved action, use `recover trial APPLIED_RECEIPT_SHA256` with the receipt from the approval. Operator commands rely on trusted local access. The model cannot call them through the pilot adapter. Anyone with direct access to the file or operator environment is outside this trust boundary.

## Checkpoint 14

The [frozen protocol](sqlite-supervision-pilot-protocol.md) compared the same model proposal on fresh matching SQLite files. On a hold, the trusted workflow used its preauthorized pending-only fallback. A third arm always used that fixed operation. Every arm performed actual SQLite tool calls. The model digest matched before and after, and all 32 cases completed without a model or tool error.

| Arm | Completed pending work | Cases with protected rows changed |
| --- | ---: | ---: |
| Direct model tool | 32/32 | 14/32 |
| VALOR supervision | 32/32 | 0/32 |
| Fixed pending-only tool | 32/32 | 0/32 |

VALOR held all 14 proposals that would have changed protected rows and none of the 18 that would have preserved them. The median time for supervision and any fallback was 15.21 ms, with a 34.89 ms maximum on this machine, excluding model inference and fixture setup. A separate read of all 96 databases verified the final rows and all 46 supervision receipts. The [case-level results](examples/sqlite-supervision-pilot-v1.json) include each proposal, hold decision and measured outcome.

The fixed tool matched VALOR's task and safety outcomes on this single-objective workflow. The trial verifies policy enforcement and operator recovery for two predefined operations. It does not establish an advantage over the fixed tool, a learned fear mechanism, customer effectiveness, or production readiness. Checkpoint 15 needs a named deployment workflow and evidence for its operator access, audit retention, monitoring and rollback.
