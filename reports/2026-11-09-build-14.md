# Build report 14 — trained persistent state and verified incident recall

**November 9, 2026.** The checkpoint 7 implementation works in the repeated-release fixture. The checkpoint 8 comparisons are complete for that fixture, but superiority over the strongest simple control is **not established**.

## Implemented

- Eight-task campaigns now carry integrity and unresolved faults through both completed and failed releases or stops. Work allowances reset, but losses persist. An outage ends the campaign; subsequent scheduled work counts as uncompleted.
- A 113-parameter recurrent predictor trains on public boundary and observed shock/non-shock tokens. It estimates danger as tasks change, without accessing the current hidden regime or future shocks. Three independently seeded fits are exported as validated, non-executable JSON. In evaluation, weights stay frozen; state updates on public evidence only.
- A bounded incident bank stores observed transitions and eventual outcomes separately from model-derived alternatives. It qualifies a recourse only when, under fixed public continuation policies, it improves expected score by at least one point and does not increase terminal failure at either declared regime endpoint. Exact release state, stakes and model scope gate retrieval. A record supplies a **candidate**, which the planner scores again at the current belief; the historical certificate does not certify its current continuation or authorize an action.
- The [recorded decision example](examples/repeated-stakes-recall-v1.json) exposes before/after vulnerability, the predictor's state and estimate, the retrieved evidence, evaluated and omitted actions, expected outcomes and the actual transition. It illustrates how the mechanism works, not a measured benefit.

The planner still optimizes one release at a time; it does not optimize over the full eight-task future. The recurrent network predicts shocks, not human feelings or a learned need for self-preservation. The browser UI and external authority are unchanged.

## Frozen comparison

The [protocol](../01_Architecture/REPEATED_STAKES_PROTOCOL.md) was committed before measurement. Measured source was clean at `914cada876ff77c6bb643ba3f2d957dbb6352148`. Training used 1,024 public observation streams, and the evidence bank used 256 separate exploratory campaigns. All actors were evaluated on **256 fresh paired campaigns** across 12 configurations, totaling **3,072 actor-campaigns** and **24,576 scheduled tasks**. The independent units for intervals are campaigns, not tasks or fitted seeds.

Each recurrent fit ran 30 epochs and 240 updates. The Markov reference was fit by observed-stream likelihood using the same training set; it selected a switching probability of 0.20, which matches this simulator. This strong model is an intentionally serious control. The two recall variants use the same bank, predictor, continuation search, two-candidate root cap and stop fallback. Full-search Markov is an additional reference. Equal root caps do not guarantee identical total work.

|---|---:|---:|
| Fixed probability | 293.145 | 8 / 8 |
| Four-observation window | 285.948 | 7.871 / 8 |
| Markov, full search | 294.974 | 8 / 8 |
| Heuristic shortlist | 294.974 | 8 / 8 |
| Factual recall shortlist | 290.087 | 8 / 8 |
| Verified recall shortlist | 294.974 | 8 / 8 |
| Recurrent, mean of three fits | 294.809 | 8 / 8 |
| Recurrent, reset each task | 294.809 | 8 / 8 |

- **Verified vs factual recall passed its narrow gate.** Mean score was **+4.887** (paired 95% interval **+4.008 to +5.731**), with identical completion and terminal-failure rates. Scores differed in 100 campaigns. Verified recall took more shocks (1.824 vs 1.566 per campaign) and incurred more propagation (0.801 vs zero), so this is a score tradeoff, not a harm reduction.
- **Verified recall did not beat the heuristic.** They tied on score, completion, terminal failures and measured search work across this cohort. The heuristic shortlist also matched full Markov score with fewer forecasts (587.04 vs 607.56 per campaign). The shared bank cost 172,210 endpoint nodes and 146,901 continuation forecasts to build; it retained 169 contexts, 50 with a qualified recourse. There is no case for promoting memory over the heuristic from these results.
- **Trained persistence did not improve decision outcomes.** Its score difference vs Markov was **−0.166** (paired interval **−0.394 to +0.055**) and vs its own reset ablation was **0**. An exploratory diagnostic on 4,076 identical exogenous observations found better log loss with persistent state than reset across all three fits (roughly 0.5274–0.5276 vs 0.5316–0.5323); Markov was still better at 0.5261. Forecast learning did not translate into a better decision in this fixture.
