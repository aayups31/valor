## Local runbook

1. Use a database created for the disposable workflow. Keep its file, backups and operator commands in directories controlled by the trusted local operator. Give the model only the proposal interface.
2. After each test batch, keep the latest receipt digest in a separate operator-controlled record. Run the health check before the next batch. A failed check means pause new proposals and inspect the retained data. The command returns a machine-readable result and exit status. The local qualification used manual checks.
3. Before a risky test and after a verified batch, keep a verified snapshot in a new file. Retain snapshots and saved digests together through the end of the test review. Confirm the retention period separately before introducing real data.
4. If the latest approved action is the only issue, use the supervisor's receipt-bound recovery command. If integrity fails, stop the workflow, preserve the affected file, restore the latest verified snapshot to a new path, and rerun the health check with the saved digest. Resume on the restored path after inspecting it. Events after the selected snapshot require separate reconciliation.

```powershell
.\.venv\Scripts\python.exe -m aace.supervision_ops artifacts/local.sqlite3 --expect-head SAVED_RECEIPT_SHA256
.\.venv\Scripts\python.exe -m aace.supervision_ops artifacts/local.sqlite3 --expect-head SAVED_RECEIPT_SHA256 --copy-to artifacts/local-backup.sqlite3
.\.venv\Scripts\python.exe -m aace.supervision_ops artifacts/local-backup.sqlite3 --expect-head SAVED_RECEIPT_SHA256 --copy-to artifacts/local-restored.sqlite3
```

The local workflow uses host access controls and receipt consistency checks. It has no separately deployed identity service, off-host audit store, automated alerts or production traffic. A party that can rewrite the database and the operator's separate records is outside this trust boundary.
