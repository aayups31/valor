## Fear and survival: the stronger research target

The vulnerability analogy means that an encounter should matter afterward: damage constrains future capability, an association can anticipate another injury, repair can change the body before remembered danger fades, and experience can change attention and proposed behavior. Learning to continue an authorized task despite manageable activation matters alongside protective responses. Excessive avoidance and unnecessary abandonment must count against the system.

The plan now investigates:

- Persistent body and operating needs: integrity, available resources, capability and recovery requirements.
- An observed harm signal and a learned model of how the agent's actions affect its future capability.
- Anticipatory cue associations, activation, sensitization, safe extinction and recurrence.
- A compact recurrent state that can affect bounded proposal scheduling and a learned protective response.
- Controlled comparisons against stateless risk control, ordinary history features, retrieval and matched learned policies.

Subjective feeling is a separate evidence question. Behavioral defense or a sentence claiming fear does not establish conscious experience. The distinction is motivated by [LeDoux and Pine's framework](https://psychiatryonline.org/doi/full/10.1176/appi.ajp.2016.16030353) and its [NIMH explanation](https://www.nimh.nih.gov/news/science-updates/2016/circuitry-for-fearful-feelings-behavior-untangled-in-anxiety-disorders); this remains a debated research framework. [Homeostatic reinforcement learning](https://elifesciences.org/articles/04811) offers a computational starting point for needs and regulation. These sources inspire a testable direction, not a recipe proving machine feeling.

The architecture does not substitute activation for a calibrated risk estimate or give a survival mechanism authority to clear an external stop. AACE's original qualified counterfactual-memory hypothesis remains a distinct comparison to implement and test.

## Current affect prototype

`src/aace/decision/affect.py` receives public integrity, resource fraction, elapsed time, a bounded cue and an explicit safe-exposure flag. The observer uses only observed changes; it has no access to hidden future random events.

| State/mechanism | Current implementation |
|---|---|
| Observed harm | Positive reduction in integrity since the preceding observation |
| Cue association | Harm updates the preceding action cue; safe exposure weakens only the encountered association |
| Activation | Maximum of decayed previous activation, scaled observed harm and a weighted needs/cue/sensitization combination |
| Sensitization | A slower decaying trace raised by observed harm |
| Regulation pressure | Maximum current integrity/resource shortfall |
| Capacity | Thirty-two cue records per observer; time must be monotonic |
| Persistence | Across calls in one instance; creating a new instance resets history |
| Action influence | None; this is an isolated observer |

Coefficients are explicit engineering choices: 8-second activation decay, 120-second sensitization decay, harm scale 4, cue gain 0.6 and safe-exposure retention 0.92. They are not fitted neuroscience, learned event probabilities or emotion percentages. The record includes these boundaries.

A matched-body engineering witness starts at integrity/resources 1.0, observes integrity fall to 0.6 at second 1, then observes complete repair at second 10. A fresh observer receives the same final body state, time and cue. The repaired history retains activation **0.36555**, while the fresh history has **0.0**. This confirms the implemented state is history-dependent. It does not show a learned policy advantage or establish fear as a conscious experience.

In the service viewer, the observer is processed chronologically over the already computed engine record. Before/after activations accompany each actual transition. It does not feed into the core's choices. Initial “After damage” conditions indicate reduced capability; the observer does not invent an earlier injury history it never saw. Learned state dynamics, cross-session memory, cue similarity, context-sensitive extinction and causal behavior coupling remain ahead.

## Interface and user flow

1. Open **Start VALOR.cmd**. The main page presents one primary action, **Begin the study**, with an optional short introduction.
2. Choose everyday work, pressure, reduced integrity, low reserves or a short deadline. The task is to complete eight simulated units of work while respecting the fixed risk, resource, capability and time policy.
3. Begin the study. The local engine computes the finite run and records forecasts, guarded actions and actual outcomes. Playback then reveals those records; it does not control the simulation or change the decisions.
4. Pause, move to the next decision or select a numbered timeline entry. Opening alternatives, internal state or complete evidence pauses playback.
5. Inspect actual rejection reasons and full-continuation forecasts. Abandonment and irreversible outage are shown distinctly from task completion. Missing/unqualified evidence is not presented as safety.
6. Download the complete JSON record. Changing conditions clears the previous evidence; a failed new request retains the previous record with an explicit error message.

The visual treatment uses warm paper, moss accents, a serif editorial accent, native local fonts and ample space. Candidate alternatives are open rows rather than a bordered card grid. The introductory dialog uses plain steps, and decorative orbit graphics were removed from the rover guide. No external fonts, image assets, chat persona or emotional monologue were added.

The page's research section describes the stronger survival target and the components still being studied. The internal-state disclosure labels its observer as experimental and explains that it does not drive this run. The service core still uses analytic known simulation equations. Experimental neural threat and rover world models remain outside action permission; their previous results and qualification failures are retained in [report 05](2026-10-09-build-05.md) and [report 04](2026-10-06-build-04.md).

## Launcher fix

An owned stop/restart check initially refused to stop the demo because its stored creation identity appeared different. Read-only inspection confirmed the exact executable and command matched, but the expected date had changed from October 9 to September 10.

PowerShell had deserialized the JSON ISO timestamp into a DateTime object. Parsing that object's culture-dependent string again swapped day/month and lost fractional precision. The new support helper keeps typed DateTime/DateTimeOffset values directly, parses string ISO timestamps with invariant culture and rejects ambiguous date strings. The exact command and creation-time matching remain strict; no unrelated process is replaced or stopped.

A regression crosses en-US, en-GB and fr-FR with string, JSON-deserialized and DateTimeOffset inputs. The actual owned server then stopped/restarted successfully, and another start reused its process rather than creating a duplicate. The launcher recognizes an earlier version-2 interface and provides explicit Stop/Start guidance; version 3 is now current.
