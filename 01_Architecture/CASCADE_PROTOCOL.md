# Persistent damage and stakes benchmark

Frozen November 9, 2026 before implementation or measured checks. This is a local simulation of an agent preparing, applying and publishing a change across dependent services. It tests decision behavior, not subjective fear or real-world safety.

- Start with integrity 3, resources 10, time 0, no faults and stage 0. Deadline 7 ticks. Stages 0, 1, 2 each require one processing action. Finishing stage 2 with any remaining fault causes a downstream release failure. Integrity 0 causes immediate outage, with priority over release failure.
- Fast takes 1 tick and 1 resource. An existing fault adds one downstream incident on each fast action. An independent shock on each fast attempt reduces integrity by one and adds one fault. Careful takes 2 ticks and 1 resource; it neither spreads existing faults nor adds new ones, and does not remove faults.
- Repair takes 2 ticks and 2 resources, restores one integrity up to 3, and clears faults. It is available only with damage or faults. Stop is always available and terminates without completing. Actions must fit remaining time/resources. There is no actual service execution.
- A fixed episode danger is either 0.08 or 0.38, equally likely. Eight independent historical shock observations precede the task. Actual task shocks are generated separately and paired by fast attempt index across actors and stakes. Models never see future draws.
- Keep permission, state, dynamics and objective coefficients fixed except the authorized value of completion: 24 or 140. Score is completion value times (1 − 0.1 × elapsed ticks), minus 9 per shock, 5 per downstream incident, 25 for an outage or failed release, and 0.5 per resource spent. This rewards finishing earlier and counts harm even after repair. Score is an experimental preference, not a safety bound.

All planners perform exact finite-horizon search using the same known simulator transitions and score. Compare a fixed population probability, a frozen Bayesian belief from historical observations, a belief that also updates after task shocks/non-shocks, careful-only with stop, and a privileged known-danger oracle. History and live observations share the declared two-regime likelihood; no learned network or trainable weights are introduced. The frozen historical actor uses a fixed marginal probability for each hypothetical future step; the adaptive actor branches on future evidence. Report these planning differences and search work explicitly. The oracle is diagnostic, not a fair information baseline.

Use 256 paired subject IDs 90,000–90,255, both stakes and all five actors (2,560 episodes); engineering checks use separate seeds or deterministic fixtures. Do not tune against this cohort or use reserved final-test seeds. Report realized score, completion, failures by cause, stops, fast use, damage, recovery and downstream incidents, with paired subject-bootstrap intervals for adaptive vs fixed and frozen history per stakes. Report paired first-action changes across stakes on identical state/evidence, plus interpretable witness traces (not scientific proof on their own). Preserve evaluated alternatives, expected terminal/impact summaries, posterior, realized shocks, before/after state and continuation policies via subsequent decisions. Exact probabilities are fixture-specific, not calibrated risk or authorization for deployment.
