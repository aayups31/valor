# VALOR product experience

Design direction recorded October 9, 2026. This guides both the present local prototype and future learned decision models.

## Premise

Make consequential decisions understandable. The visitor can try a bounded task, watch what VALOR chose, and inspect why another option was rejected. Damage, scarce resources and time pressure make the research question concrete. The interface must not imply subjective feeling, universal capability or evaluated futures beyond the recorded candidates.

## Reference interpretation

The owner supplied Scale's public homepage and a local 10K Websites workflow. Scale was visually reviewed on October 9: white navigation, a large immersive scientific hero, restrained type and clear content hierarchy. The folder contains workflow documents, not ready-made design assets. Its coherent premise, deliberate copy, vector layers and static/reduced-motion fallback inform this work. The request concerns VALOR's existing local UI; account creation, generated paid films and external hosting are outside its scope.

VALOR uses an original code-native contour composition. It evokes branching choices without presenting decorative curves as model activity. The visual is explicitly an illustration. No Scale logos, footage, customer claims or testimonials are reused.

## Visitor journey

1. Understand the question and select **Try VALOR**. The default pressure scenario starts locally.
2. Choose among five readable situations, then run or rerun beside the experiment.
3. Read progress, resource reserve, system health and time left. Optional inline guidance defines them.
4. Follow one actual choice. Separate the plan's predicted consequences from the observed outcome of the applied action.
5. Pause, step through, or select an earlier record. Opening evidence pauses playback.
6. Inspect alternatives, experimental internal state or the complete downloadable record when needed.
7. Learn the current research boundary and direction. The rover is a secondary benchmark.

## Visual system

Warm white page, dark ink hero, pale amber contour lines and a restrained clay accent. Local system typography only: Segoe UI Variable / Segoe UI for display and body, system monospace for records and fine labels. Generous open rows, hairline separators, rounded controls and one immersive hero surface. No tiled dashboard. No external assets, fonts, subscriptions or media pipeline.

Small screens retain the same controls and reading order. Motion is optional; reduced motion starts a run paused, and every result can be inspected without animation. Color is accompanied by labels, focus is visible, controls have usable touch targets, and long records scroll within their own region.

## Future model integration

Keep the interaction contract while changing the engine: scenario -> bounded run -> chosen action -> forecast -> actual outcome -> evidence. Name whether a forecast is analytic, learned, calibrated or unsupported. Show internal activation separately from risk estimates and clarify whether it affects choices. Show failure and abandonment plainly. Learned recurrent state, memory and world-model comparisons should enter this same experience when implemented and tested, without invented thought transcripts or simulated training progress.

The present demo still uses known service simulation equations and an observer that does not select actions. Premium presentation is not research validation.
